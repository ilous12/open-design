# Design For AIR

통신사 조직의 전문 디자이너, 개발자, 기획자가 함께 사용하는 로컬 우선 디자인 워크스페이스입니다.  

핵심 관점은 단순합니다.  
실무자는 요구사항을 글로만 넘기고 끝내는 것이 아니라, 레퍼런스와 디자인 시스템, HTML 기반 프로토타입, 리믹스 가능한 산출물을 함께 다루며 더 빠르게 의사결정해야 합니다. Design For AIR는 그 흐름을 코딩 에이전트와 저작도구 중심으로 다시 묶습니다.

## 왜 Design For AIR인가

기존 AI 디자인 도구를 사용하며 느낀 문제의식은 분명했습니다.

- 디자인 토큰과 조직별 문맥이 충분히 반영되지 않으면 결과물이 쉽게 일반론으로 흐릅니다.
- 실무 협업은 "좋은 문장"보다 "바로 수정 가능한 산출물"이 더 중요합니다.
- 별도 디자인 전용 사용량을 늘리기보다, 이미 보유한 코딩 토큰을 활용하는 쪽이 더 현실적일 때가 많습니다.
- 통신사, 본사, 대리점, 영업점처럼 이해관계자가 많은 조직에서는 레퍼런스 재사용과 빠른 리믹스가 특히 중요합니다.

Design For AIR는 이 문제를 다음 방식으로 풉니다.

- 코딩 에이전트를 디자인 실행 엔진으로 사용
- 조직 전용 디자인 시스템과 프롬프트 규칙을 누적
- 레퍼런스와 HTML 결과물을 프로젝트 단위로 저장, 복사, 리믹스
- 저작도구 기반 산출물을 바로 검토하고 수정
- 로컬 우선 구조로 프로젝트와 설정을 통제

## 제품 스토리라인

### 1. 페인포인트

- 기획 문서와 디자인 결과물 사이 간극이 큽니다.
- 화면 요구사항이 텍스트로만 전달되면 해석 오차가 반복됩니다.
- 디자인 시스템이 약하면 결과물 톤앤매너가 계속 흔들립니다.
- 운영 조직은 빠른 시안이 필요하지만, 정교화 단계에서 다시 처음부터 손보는 일이 많습니다.

### 2. 해소 방식

- 통신사 디자인 시스템을 기준으로 기본 톤, 컬러, 타이포, 컴포넌트 규칙을 강제합니다.
- 웹/모바일 프로토타입 중심으로 결과물을 빠르게 만들고, 바로 미리보기합니다.
- 레퍼런스를 앱 내부에서 관리하고, 필요한 경우 프로젝트로 리믹스해 이어서 수정합니다.
- 코딩 토큰을 활용해 반복 시안 제작과 수정 비용을 낮춥니다.

### 3. 구현 방향

- 로컬 CLI 기반 실행: `Codex CLI`, `Antigravity CLI`, `Claude Code CLI`
- 또는 BYOK API 모드로 실행
- 프로젝트 단위 산출물 관리
- HTML 기반 미리보기와 편집
- 통신사 서비스 맥락에 맞춘 한국어 기본 경험

## 현재 제품이 집중하는 것

Design For AIR는 현재 다음 흐름에 집중합니다.

- 웹 프로토타입 생성
- 모바일 프로토타입 생성
- 레퍼런스 탐색 및 리믹스
- 통신사 디자인 시스템 기반 화면 정교화
- 프로젝트 저장, 복사, 재편집

즉, "무엇이든 다 하는 범용 생성기"보다  
"실무 조직이 바로 쓰고 고칠 수 있는 디자인 작업 환경"에 더 가깝습니다.

## 누가 쓰는가

- 전문 디자이너: 초기 시안 탐색, 디자인 시스템 검증, 화면 정교화
- 개발자: 실제 구현 가능한 형태의 프로토타입 작성, 구조 파악, 리믹스 후 코드화
- 기획자: 문서형 요구사항을 바로 확인 가능한 화면 산출물로 전환
- 운영/사업 조직: 서비스 현황판, 관제형 화면, 영업/상담 지원 화면의 빠른 시안화

## 차별점

- 글 설명에서 끝나지 않고, 저작 가능한 결과물로 이어집니다.
- 조직 전용 디자인 시스템을 기반으로 결과물의 일관성을 높입니다.
- 코딩 토큰을 활용하므로 디자인 실험량을 늘리기 좋습니다.
- 반복 시안 제작과 수정에 드는 부담을 줄이기 좋습니다.
- 레퍼런스를 "보기"로 끝내지 않고 "리믹스 가능한 프로젝트 시작점"으로 사용합니다.
